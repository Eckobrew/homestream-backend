# HomeStream 1.1 follow-up changes

## Upgrade existing state

The backend now uses SQLite (`homestream.sqlite`) rather than writing JSON files. Stop the old backend and back up the entire data directory before migration. Build the new backend, then run:

```bash
npm run storage:import -- /absolute/path/to/data
```

For a built Docker image, before starting the regular service:

```bash
docker compose -f deploy/compose.yml run --rm backend node dist/import-state.js /app/data
```

The importer validates configuration, unique profile IDs, device credentials and parental state before creating the database. It imports everything in one transaction, preserves linked IDs/PIN hashes, hashes existing device credentials, retains the original JSON files and creates a private backup directory. An identical retry is harmless. A different existing database is never overwritten. Missing PIN data with Kids profiles or invalid JSON stops migration.

Run migration as the service account (UID 1001 in Docker), or set database ownership to that account before restarting. For LXC, use `runuser -u homestream -- node /opt/homestream-backend/dist/import-state.js /var/lib/homestream`.

Fresh installations create an empty database without an import. An existing JSON installation requires explicit import. A missing database after initialization fails closed using a persistent marker. Do not run multiple backend instances against one data directory.

Create a consistent database backup while running:

```bash
DATA_DIR=/absolute/path/to/data npm run storage:backup -- /absolute/path/to/backup.sqlite
```

Backup output must not already exist. Keep backups private: they contain integration secrets and parent policy. For rollback, stop the new backend and restore the original complete JSON backup with the previous backend image. Changes made after import will not exist in that older JSON backup. For a current-version database restore, stop the backend and restore the SQLite backup together with the data directory marker. Never restore over a running writer.

## Conversion limits

`HOMESTREAM_MAX_CONVERSIONS` defaults to 2. Excess conversions receive 503 and `Retry-After: 5`; direct file streams do not consume a conversion slot. Requests, failed spawns, process exits, timeouts and shutdown are covered by lifecycle tests. `HOMESTREAM_CONVERSION_TIMEOUT_MS` defaults to six hours. Conversion logs contain an ID and duration, not source URLs or credentials. Measure CPU/memory and startup latency on your target machine before increasing the limit.

## API and clients

The 1.1.0 OpenAPI contract describes all 58 web/native operations, their supported query/body fields, authentication, policy errors and streaming/range responses. Shared JSON schemas validate requests at the HTTP boundary; native authorization runs before protected request validation. Legacy handlers retain additional semantic checks.

`npm run contract:check` regenerates and compares the contract and checks compatibility against the complete 1.1 baseline. To compare another released artifact, run `node scripts/compare-contract.mjs previous-openapi.json contract/openapi.json`. Operation removals, required-parameter/body additions, response-field removals, type changes and enum narrowing are rejected without a major version increase. Update the checked-in baseline only as part of a reviewed release.

`npm run contract:kotlin` generates Android-compatible Kotlin models and a blocking OkHttp client. Compile using JDK 21 with `cd contract/kotlin && ./gradlew compileKotlin --no-daemon`. The generated bytecode targets Java 8. Run calls off the Android main thread. Stream/image calls return an OkHttp response that must be closed; they do not buffer videos. Mixed JSON unions use `JsonElement`. Web client snapshots and Kotlin sources are included in the API package.

## UI and playback

One setup wizard owns server connection, profile import/creation and completion. Blank password/key fields preserve stored credentials; a connection failure keeps the user on the server step. The hidden sidebar is excluded from focus and accessibility navigation. Demo artwork is local and visible naming no longer uses HomeFlix or a hard-coded external domain.

Playback negotiation, retry cancellation, native/HLS delivery, progress sessions, subtitles, Cast listeners and playback-state derivation have dedicated modules. Each item owns its progress session, old requests are aborted on item change, and closing clears timers/listeners and releases media resources. A new episode uses its own resume position, including zero.

## Failures, diagnostics and maintenance

`HOMESTREAM_DEMO_MODE=false` is the default. Sample content and simulated requests require explicit opt-in; an outage of a configured Jellyfin server never replaces the library with sample titles. The UI offers retry on unavailable feeds.

Internal endpoints distinguish `/health/live`, `/health/ready` (state storage), `/health/dependencies` (last observed upstream results), and `/health/metrics` (API/upstream/conversion counts and durations). Dependency results are observations, not active probes. Every response has a generated `X-Request-Id`; upstream headers have bounded timeouts. Credentials and credential-bearing URLs remain redacted.

Both repositories use ESLint 10 flat configuration with an enforced baseline on new/extracted modules. Legacy modules remain under type checking and integration coverage rather than receiving an unreviewable lint rewrite. CI runs lint, contracts, migration/conversion tests and Kotlin compilation. Renovate configuration groups related updates weekly; enabling the Renovate app in GitHub remains an account-side step. MIT licensing is explicit; dependency and Gradle wrapper licenses remain separate.
